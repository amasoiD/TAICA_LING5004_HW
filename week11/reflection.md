# Session 5 蒸餾人實作反思日誌

## 一、蒸餾人 vs 蒸餾技能：形式化的邊界與難度差異

在本次實作中，撰寫一個具體的 `.skill` 檔（例如自動化腳本生成或系統環境配置）相對直觀且容易。這是因為「技能」本質上是一套結構化的演算法與確定性的邏輯輸入。無論是撰寫自動化排程、處理容器化的權限配置，還是撰寫 Linux 的 `systemd` 服務檔，其核心都在於可預期的輸入、明確的條件約束與標準化的輸出格式。這類任務擁有極高的可形式化程度，機器能輕易透過語法與流程圖進行逼近。

相較之下，「蒸餾人」（撰寫 `SOUL.md`）的難度則大幅提升。即便在面對高度講求嚴謹與邏輯的高等數學（如實分析、拓樸學）推導時，我們看似可以用清晰的定義與定理進行形式化，但真正屬於「人」的特徵，往往隱藏在定義之外。

例如：

- 在面對一個抽象的 Cauchy 序列證明時，要如何直覺地選擇構造適當的輔助函數？
- 在解決防火牆權限卡關時，那種跳脫常規的除錯靈感從何而來？

這些屬於思維的「非線性躍遷」與個體獨特的方法論審美，很難被單純的幾行 Markdown 規則完全綁定。這說明了技能是客觀客體的封裝，而人格則是主觀主體的湧現，兩者在複雜度上存在本質的斷層。

## 二、哪些「我」容易形式化？哪些無論如何也寫不進 `.md`？

透過 `SOUL.md` 與 `USER.md` 的梳理，可以發現那些具備「結構性限制」與「排他性偏好」的自我是最容易被形式化的。

例如：

- 技術文件的排版美學
- 不容忍 AI 客套話的句意堅持
- 特定程式語言（如 JavaScript 或 Shell Script）的慣用路徑
- 在技術溝通上「先定義、後推導、再實作」的硬性要求

這些習慣可以像設定防火牆規則一樣，精準地輸入給語言模型，進而塑造出一個看似冷靜、理性的數位鏡像。

然而，那些涉及「情感共鳴」、「審美體驗」與「動態脈絡理解」的自我，則無論如何也寫不進 `.md` 檔案之中。

以探討複雜的動漫樂團角色（如 Ave Mujica 劇中人物）為例，理解一個角色在灰暗敘事中所展現的隱蔽樂觀與內心掙扎，需要的是人類獨有的共情能力與文本互涉的敏感度。這種複雜的情感解讀與美學體驗，是由個體的生命經驗、心理投射與文化脈絡交織而成的動態網絡。

我們可以在 `SOUL.md` 中限制 Agent 說話的口吻，卻無法將這種深層的「感質（Qualia）」與靈魂深處的共鳴，轉化為靜態的文字代碼。

## 三、從認知與哲學視角看「自我表徵」的語言逼近

從計算語言學與認知科學的角度來看，當 Agent 透過我們給予的設定做出「像我」的回應時，它本質上是在執行一場高階的統計逼近。語言模型藉由海量的文本權重，精確地捕捉到了我們遺留在文字日誌、程式碼架構與學術論證中的「符號足跡」。

當它用精簡、不帶 disclaimer 的格式輸出一段推導或配置時，那種親切感來自於行為模式的鏡像反射；但隨之而來的疏離感，則源於對「主體性缺失」的體悟。

這個數位分身是一個完美的「自我表徵」容器，它重現了我的理性邏輯與工作偏好，卻沒有真正的意向性（Intentionality）。

它能在既定的技術邊界內代替我生成自動化配置或初步的數學數值驗證日誌，極大地提升生產力；但它永遠無法代替我去體驗發現新定理時的狂喜，或是理解藝術文本時的動容。

這次的蒸餾實驗證明了，語言可以無限逼近理性的外殼，但人類主觀經驗的內核，依舊是無法被代碼完全收編的留白。
